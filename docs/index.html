Native NVMe, one switch

Enable or disable the hidden Windows Feature Management overrides that unlock experimental Native NVMe support — via one-click script, .reg files or a small .NET tool, with a clean rollback.

Download View on GitHub
Unofficial and experimental on Windows 11. Microsoft supports Native NVMe only on Windows Server 2025. Create a restore point first.

Three DWORD values, nothing else

On many Windows client installs, NVMe SSDs go through a SCSI/Storport path (disk.sys). With these overrides they can show up under Storage disks and use a dedicated NVMe path.

Possible gains

Better numbers in some metrics: IOPS, reads and writes at certain block sizes.

Known caveats

On some systems: duplicate or unrecognized drives, management tools that lose the NVMe.

Clean rollback

Disable removes exactly the three values it created. Everything is under HKLM, so it needs administrator rights.

Four ways, same result

Everything requires an elevated (administrator) prompt.

One-click menu

scripts/installer.ps1: Enable, Disable, Status and an optional Safe Mode fix.

PowerShell scripts

set-overrides.ps1, remove-overrides.ps1, status-overrides.ps1, non-interactive.

.reg files

reg/feature-overrides-enable.reg and reg/feature-overrides-disable.reg, double-click.

.NET tool

FeatureOverridesSetter.exe status | enable | disable. Self-contained, nothing to install.

# elevated PowerShell
powershell -ExecutionPolicy Bypass -File .\scripts\installer.ps1

Download and verify

Every release has SHA256SUMS.txt and VERIFY.ps1: put them in the same folder as the files and run the script.

powershell -ExecutionPolicy Bypass -File .\VERIFY.ps1

Requires Windows x64 and administrator rights. The exe is self-contained (.NET 10 inside).
